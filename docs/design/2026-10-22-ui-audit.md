# VideoAdjust UI audit, 22 October 2026

Review mode: full overhaul audit. Designing: a browser video tool for people shrinking, trimming, comparing, or extracting audio from a local file, vibe practical and private, on desktop and mobile web, using the existing VideoAdjust system. Variance 3/10 because editing controls need predictable placement; density 5/10 because file facts matter but should not compete with the task; motion 2/10 because motion should report processing or preview state.

## Design health

**At risk.** The local-processing message, one main task per state, native video preview, warm neutral palette, and 44 px base target are useful foundations. The desktop drop screen spends most of its area on a generic upload frame and disconnected hero. The editor then changes to a dense two-column layout whose header, canvas, rail content, and action do not share a clear axis. On phones, the fixed export action appears before the warning and settings in the reading order. No blocking flow or contrast failure was established from these artifacts, so no finding is rated CRITICAL.

Evidence: the supplied `desktop-*`, `tablet-*`, `phone-*`, and `final/` screenshots, `src/styles/tokens.css`, `src/styles/app.css`, `index.html`, and `src/ui/*.ts`. Screenshot coordinates below are approximate CSS pixels; desktop PNGs are 2x captures of a 1440 px viewport. The `final/` phone captures show the same layout with a few different capture frames.

## Prioritized fixes

1. **Structural, A01:** Rebuild the desktop drop grid around the file choice. Align the copy and picker, reduce the frame height, and remove the viewfinder corners and redundant steps.
2. **Structural, A02:** Expose the “already small” caveat before the fixed phone action. Keep the full explanation in the settings panel.
3. **Structural, A03 and A04:** Align desktop tabs with the work canvas and give the inspector a stable action position. Treat header, canvas, and rail as one grid.
4. **Quick win, A05 and A07:** Set one rail inset and enforce the existing spacing and radius tokens across adjacent components.
5. **Quick win, A06, A08, A09, A11:** Establish button tiers and a single app icon family, then clean up the result transport and icon-only cues.

Modernization order: typography and spacing first; color and emphasis second; desktop grid and hierarchy third; icon, button, and component states fourth; motion last. Keep the current task sequence, navigation labels, URLs, logo, privacy claim, and legal copy unless separately approved for change.

## Button and icon rules

These values are a proposed VideoAdjust specification. They use the current 44 px `--tap`, 4 px spacing base, and 24×24 icon sprite as starting points.

| Rule               | Concrete value                                                                                                                                                                                                                                                                                         |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Action tiers       | One filled primary per state: Choose video, Export or Extract audio, then Download. Outlined secondary for trim cues and a recommended adjustment. Quiet text action for reset or replacing the file.                                                                                                  |
| Size and padding   | Minimum 44×44 px hit area; ordinary text button 44 to 48 px high with 16 px horizontal padding; major primary 52 to 56 px high with 20 to 24 px horizontal padding. Keep controls in one group at the same height.                                                                                     |
| Label and icon     | Sentence-case verb label, 14 to 16 px type. Keep filenames, estimates, and helper text outside the button. Use a 20 px icon and 8 px icon-label gap in ordinary buttons; 16 px and 4 px only for compact metadata. Center icon and label as one unit.                                                  |
| Radius and spacing | 10 px control radius, 14 px card radius, 6 px inset control radius, circular only for a play control or drag knob. Use 8 px within a button group and 16 to 24 px between unrelated action groups.                                                                                                     |
| States             | Specify default, hover, pressed, keyboard focus, disabled, and busy. Keep the existing visible 2 px focus outline, show a busy label during export, and avoid color-only state changes.                                                                                                                |
| App icon family    | One 24×24 artboard and a consistent 1.5 to 2 SVG-unit stroke, using round caps and joins for app-owned stroke icons. Render at 20 px in controls, 16 px in metadata, and 24 px for a standalone symbol. Check optical size and center against neighboring icons at each rendered size.                 |
| Icon-only actions  | Reserve for familiar transport and theme controls or space-constrained drag handles. Keep accessible names already present in code; add a visible cue or tooltip where meaning is less obvious, especially the comparison wipe. A decorative icon next to text stays hidden from assistive technology. |

The hierarchy and short verb labels follow [USWDS button guidance](https://designsystem.digital.gov/components/button/). Its examples also cover hover, active, disabled, and focus states. [Carbon button guidance](https://www.carbondesignsystem.com/building-blocks/core/components/button/guidelines) recommends sparse icon use and consistent button sizes within a group; its [button specifications](https://www.carbondesignsystem.com/building-blocks/core/components/button/specifications) give a concrete 8 px gap for a ghost button icon. [Carbon icon guidance](https://www.carbondesignsystem.com/building-blocks/foundations/icons/guidelines) calls for consistent icon size, optical alignment beside text, and 44 px interactive targets. [Lucide’s icon guide](https://lucide.dev/contribute/icons/inkscape-guide) demonstrates a 24 px grid with a 2 px stroke. [USWDS icon guidance](https://designsystem.digital.gov/components/icon/) recommends pairing ambiguous icons with text. [Atlassian’s icon guidance](https://atlassian.design/guidelines/product/foundations/iconography) describes optical balancing, so equal view boxes alone are insufficient.

## What was not verified

- The PNGs show fixed captures, not pointer, keyboard, touch, screen-reader, loading, error, or share behavior. Source inspection confirms accessible names on the app-owned icon-only buttons, but does not prove usability.
- Contrast, target geometry in every state, zoom at 200% and 400%, forced colors, and reduced motion were not measured in a browser.
- Browser-native video controls vary by browser and operating system. The mixed-control observation concerns the captured appearance, not a proposed replacement of native playback.
- Layout beyond the supplied viewport widths, including screens wider than 1440 px, was not rendered. Recognition and task impact need real user testing.
